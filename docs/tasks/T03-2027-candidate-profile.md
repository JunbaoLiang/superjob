# T03 — 更新 2027 候选人档案

状态：`complete`
优先级：P0

## 目标

将活跃候选人档案中的过期毕业年份、可用时间与工作授权表述更新为用户已确认的 2027 求职事实。此任务只维护当前事实来源，不生成或覆盖任何岗位材料。

## 修改范围

仅允许修改以下活跃档案：

- `<project-root>/data/profile/resume-master.md`
- `<project-root>/data/profile/target.md`
- `<project-root>/data/profile/preferences.md`（仅在需要使生成规则与更新后档案一致时）

## 已确认的事实边界

- 学位预计于 2027 年 5 月完成。
- 实习面向 Fall 2026 与 Spring 2027；不寻找 Summer 2027 internship。
- 全职可用时间窗口为 2027 年 3 月至 5 月。
- 工作授权、长期 sponsorship 与个人移民规划仅按用户已确认的表述更新；不得推断资格、承诺或雇主政策。
- 没有待加入的新论文、项目、合作、TA/RA、奖项、实习或 GitHub 项目。

## 授权边界

仅在用户回复“授权执行 T03-A”后执行实际档案修改。

允许：

- 修正活跃 summary、education、职位目标、实习/全职窗口和工作授权说明。
- 删除与已确认事实冲突的过期 2026 表述与无内容 TODO 注释。
- 保留当前已确认的项目、论文、技能、链接和数字，不新增未经确认的事实。

禁止：

- 修改 `data/jobs/` 下任何已投递或被拒岗位、历史简历、求职信或导出文件。
- 编造经历、技能、论文、量化结果、工作资格或职位偏好。
- 将档案内容加入 Git、推送远端、部署或生成新申请材料。

## 执行步骤

1. 执行前只读记录三个活跃档案的现状，并确认历史岗位目录不在修改范围。
2. 更新主简历中的候选人身份与 education 日期，使其与 2027 事实一致。
3. 更新目标档案中的毕业年份、实习/全职窗口与用户确认的工作授权表述；明确职位评分不能将未说明 sponsorship 当作自动不合格。
4. 仅在必要时调整生成偏好，确保材料可在一页内且不引入新事实。
5. 检查活跃档案没有残留过期毕业年份；检查没有修改 `data/jobs/`；将修改以 diff 形式交给用户复核。

## 验收标准

- 三份活跃档案不再将候选人表述为 2026 毕业。
- 主简历中的候选人身份与 education 日期一致，且只使用用户确认的事实。
- 目标档案正确区分实习与全职时间窗口，以及已确认的工作授权与长期 sponsorship 需求。
- 无新增或夸大的经历、技能、数字、资格或职位偏好。
- 历史岗位数据和材料没有变更；不产生 Git 提交、推送或部署。

## 完成后的交付

报告修改文件、事实变更摘要、验证结果、保留的风险，以及下一张任务卡建议：T04 — 历史与活跃岗位处理规则。
