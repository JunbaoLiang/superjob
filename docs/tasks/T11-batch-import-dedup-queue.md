# T11 — 批量导入、去重与可见队列

## 目标

让本地优先工作流一次接收多个职位 URL 或 JD 文本，并以可追踪、可重试的方式逐个解析和评分；绝不自动申请、发送外联或生成材料。

## 边界

- 仅处理用户显式提交的 URL/JD；不实现自动搜索或网页抓取。
- 不读取、重写或删除既有职位、档案、历史材料。
- `applied`/`rejected` 历史记录持续冻结；导入只创建新记录或报告重复。
- 队列失败必须保留错误和原始输入摘要，供用户选择重试；不得伪装为成功。
- 任何导入结果仍受 Eligibility/Match 和 readiness 闸门约束，不能改变自动投递边界。

## 去重规则

1. 规范化 URL（去空白、片段及常见追踪参数；保留来源、路径和实质查询参数）完全相同：报告为重复，不创建新记录。
2. 两边均无 URL 时，规范化后的公司、职位、地点完全相同：报告为重复，不创建新记录。
3. 仅公司和职位相同、但 URL 或地点不同：报告为 `possible-duplicate`，保留用户输入，不自动合并。

## 分阶段执行

### T11-A — 离线核心与测试

- 先以临时目录 fixture 覆盖 URL 规范化、精确重复、可能重复、队列状态机、失败记录与重试。
- 实现独立的批量输入解析/去重/队列模块；不调用 LLM，不读取真实 JD 或岗位目录。
- 运行完整本地/云端离线测试、语法和 diff 检查。

### T11-B — 本地 API / CLI 接入

- 增加本机同源批量导入接口、CLI 输入和队列状态/失败列表；沿用单工人串行处理。
- 在临时 fixture 中验证批量请求、失败可见和显式重试；不导入真实职位、不调用模型。

### T11-C — 面板与扩展入口

- 增加粘贴多条 URL/JD 的入口和队列反馈，并验证扩展/面板权限边界。
- 保持现有单职位扩展抓取；不添加自动申请、自动表单填写或自动外联。

## 验收

- 连续批量导入不会因 URL 精确重复而新建岗位。
- 可疑重复不会被静默删除。
- 每个任务都有 `queued`、`running`、`succeeded` 或 `failed` 终态，失败原因可见并可显式重试。
- 单个失败不阻塞后续任务。
- 离线测试不调用真实 LLM、不产生 API 成本，也不修改 `data/`。
