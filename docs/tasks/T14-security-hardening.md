# T14 — 安全加固

## 已发现风险

本地与云端 Markdown 预览会转义正文，但链接渲染直接将 Markdown URL 写入 `href`。因此恶意 JD、报告或材料中若含 `javascript:` 等协议，可能生成可点击的不安全链接。

## 目标与边界

- 仅允许 Markdown 链接使用 `https:`、`http:`，以及内部受控的相对下载链接；其他协议显示为纯文本。
- 外部链接加入 `rel="noopener noreferrer"`。
- 不读取或修改真实岗位、材料、token、profile；不上传任何数据。
- 本轮不更改扩展权限、不创建云端资源；这些另列后续子任务。

## 执行顺序

1. 为本地与云端 Markdown 链接清洗器写 fixture 测试，覆盖 `javascript:`、`data:`、畸形 URL 与正常 HTTPS。
2. 统一协议白名单逻辑，应用到预览与“原始职位”外链。
3. 添加 CSP/输入大小边界审查并在不破坏书签功能的前提下实施。

## 验收

- 恶意协议不会出现在输出 `href`。
- HTTPS 职位和资料链接仍可访问，且带安全 `rel`。
- 所有测试离线运行，不调用模型或浏览器抓取。
